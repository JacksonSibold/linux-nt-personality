## 8. Method and limits

- Area status comes from `docs/phase2/ARCHITECTURE-STATUS.md`, `docs/status/SERVICES.md`, `docs/KNOWN-ISSUES.md`, the review reports and the decision index. A status describes what the code contains, not whether it works.
- Effort starts from the area status and adds one step when the environment needs a booted personality kernel or a VM. Documentation-only checks are S. Gated and out-of-scope criteria are `unknown`. The reasoning for each criterion is in section 3.
- The graph is at the granularity of an area plus keyword refinements. Criteria in the same area share work items unless a keyword narrows them, so the order is a plan, not a measurement.
- The last gate is the deepest work item of a criterion. When two items are equally deep, the one later in ID order is named; every work item in the criterion's closure must be done before it can pass.
- Traceability classes come from `tools/criteria_trace.py`. A registry entry is not a pass.
