# Module: debugobj (DEBUG objects)

Sources: `src/kernel/nt/debugobj.c`, `src/kernel/nt/debugobj.h`
Hooks outside the module: `object.h` (the `debug_obj` field of `struct nt_eprocess`), `object.c` (weak no-op `nt_debug_post_event`), `proc_thread.c` (event posts on thread create, thread exit and process exit).
Related: `job.md` (the same object model), `sync.md` (the wait engine used to block `NtWaitForDebugEvent`), `object.md` (object types and references), `proc_thread.md` (thread and process termination).
Host test: `tests/kernel-host/debugobj_test.c` (13 tests, run by `make check-quick`).

## Purpose

A DEBUG object is a queue of state changes for the processes attached to it. A debugger attaches a process, waits for events, and resumes each event. Its services are `NtCreateDebugObject`, `NtDebugActiveProcess`, `NtRemoveProcessDebug`, `NtWaitForDebugEvent` and `NtDebugContinue` (SSNs 0x00a8, 0x00d2, 0x0179, 0x01d9, 0x00d3). Before this module they were `MISSING` in [SERVICES.md](../status/SERVICES.md).

`NtSetInformationDebugObject` is implemented too, but `nt_service_list.h` has no SSN for it, so it is reachable only from the host tests. No SSN was invented for it.

## Public API (debugobj.h)

- `nt_debug_object_type`: the object type, named `DebugObject`.
- `nt_debug_post_event(proc, state, tid, status)`: queues a state change for `proc` if a debugger is attached. Called from `proc_thread.c`.
- `DBGUI_WAIT_STATE_CHANGE` and `DBG_STATE`: the event structure. The fields this module fills keep the NT layout (`NewState`, `AppClientId`, `ExitThread`, `ExitProcess`). The exception and DLL payloads are not defined.
- Access rights: `DEBUG_OBJECT_WAIT_STATE_CHANGE` (0x1), `DEBUG_OBJECT_ADD_REMOVE_PROCESS` (0x2), `DEBUG_OBJECT_SET_INFORMATION` (0x4), `DEBUG_OBJECT_ALL_ACCESS`. `DEBUG_KILL_ON_CLOSE` (0x1) is the create flag.
- Continue statuses: `DBG_CONTINUE`, `DBG_EXCEPTION_NOT_HANDLED`.

## Attachment and lifetime

- A process holds at most one debug object (`proc->debug_obj`). A second attach is `STATUS_PORT_ALREADY_SET`.
- Attach needs `PROCESS_SUSPEND_RESUME` on the process handle and `DEBUG_OBJECT_ADD_REMOVE_PROCESS` on the debug handle. A process cannot debug itself (`STATUS_ACCESS_DENIED`). A terminated process is `STATUS_PROCESS_IS_TERMINATING`.
- An attachment holds a reference on the process object and on the debug object. Neither can be freed while attached.
- `NtRemoveProcessDebug` detaches and discards the queued and awaiting events of that process. A process that is not attached is `STATUS_PORT_NOT_SET`.
- Closing the last debug handle detaches every process. With `DEBUG_KILL_ON_CLOSE` (or the `DebugObjectKillProcessOnExitInformation` class) each detached process is terminated with exit status `STATUS_SUCCESS`.

## Events

| Event | Generated by |
|---|---|
| `DbgCreateProcessStateChange` | Attach (queued for the target process). |
| `DbgCreateThreadStateChange` | `NtCreateThreadEx`, after the thread handle exists. |
| `DbgExitThreadStateChange` | The thread start-routine return path, and `NtTerminateThread` for the current and another thread. Carries the exit status. |
| `DbgExitProcessStateChange` | `NtTerminateProcess` for the current and another process. Carries the exit status. |

Not generated: `DbgExceptionStateChange`, the breakpoint and single-step states, and the DLL load and unload states. The tree has no exception-dispatch hook that reaches a debug object. Process termination through the job kill path (`NtTerminateJobObject`, kill on job close) posts no event.

A post for a process with no debugger is one pointer check. A post that cannot allocate is dropped.

## Waiting and continue

- `NtWaitForDebugEvent` dequeues the oldest event (FIFO) and moves it to the awaiting list. An empty queue blocks through the sync wait engine (`nt_wait_for_single_object` on the object's auto-reset event). `Timeout` NULL waits forever, zero polls, and a relative or absolute value expires with `STATUS_TIMEOUT`. `Alertable` returns `STATUS_USER_APC` when an APC is pending. The event stays signaled while the queue is non-empty, so another waiter wakes for the next event.
- The timeout applies to each wait. A wake that finds the queue empty again (another waiter took the event) starts a new wait with the same timeout, so the total can exceed the requested time.
- `NtDebugContinue` matches the `ClientId` (process and thread) of an event on the awaiting list and removes it. Only `DBG_CONTINUE` and `DBG_EXCEPTION_NOT_HANDLED` are accepted. Any other status, or a `ClientId` with no awaiting event, is `STATUS_INVALID_PARAMETER`.

## Locking

Lock order: `dbg->lock`, then `proc->lock`. The post path takes `proc->lock` alone to read `proc->debug_obj`, takes a reference on the debug object, releases the lock, and then takes `dbg->lock`. Thread termination (`ObTerminateProcessThreads`) runs after both locks are released. The wait path holds `dbg->lock` only to check the queue and reset the event, never across the wait.

## Known gaps

- No exception, breakpoint, single-step or DLL events (see Events).
- `NtSetInformationDebugObject` has no SSN in `nt_service_list.h`. It is tested but not dispatchable.
- Only one information class (`DebugObjectKillProcessOnExitInformation`, a `BOOLEAN`). There is no query.
- `DBG_REPLY_LATER`, `DBG_TERMINATE_THREAD` and `DBG_TERMINATE_PROCESS` are refused. Continuing with a termination status has no effect in this tree.
- Attaching does not suspend the target, and it does not synthesize create-thread or DLL events for threads that already exist.
- The kernel ABI wrappers (`__KERNEL__` branch at the end of `debugobj.c`) are not compiled by the host build or by `tests/syntax/check.sh`, which define `USERSPACE_KSHIM`. The kernel build has not been run.

## Tests

`tests/kernel-host/debugobj_test.c` (run from `make check-quick`):

1. Create (NULL pointer and unknown flags refused), 2. access masks on attach, remove and wait, 3. attach needs `PROCESS_SUSPEND_RESUME`, 4. self-debug refused, 5. one debugger per process, 6. attach event, timeout and continue matching, 7. relative timeout and an alertable wait with a pending APC, 8. thread and process exit events with exit statuses, 9. remove purges queued events, 10. close detaches without killing, 11. kill on close flag, 12. kill on exit information (access, length and class checks), 13. multi-thread wait: three threads block in `NtWaitForDebugEvent` and each dequeues exactly one posted event. The test ends with a leak check (`kshim_alloc_count`).
