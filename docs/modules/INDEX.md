# Kernel NT personality: module reference index

These pages describe the modules under `src/kernel/nt/`. Each page covers purpose, public API (taken from the headers), key data structures, invariants and locking as they appear in the code, and known gaps visible in the code or the project README.

The project is an incomplete research prototype (see the top-level `README.md`). Nothing here has been built or run in a kernel. Claims about behaviour come from reading the source, and line references are to the files as they exist in this repository at the time of the last refresh (2026-10-12). Host tests under `tests/kernel-host` build and run the userspace branch of most modules.

## Cross-module notes

- **Handles and objects.** `handle` resolves handles to `object` headers and takes references. `io`, `registry`, `sync`, `iocp`, `mm` (sections) and `proc_thread` create their objects through the object manager.
- **Dispatch.** `dispatch` routes SSNs to `nt_svc_*` functions. Most are defined in the modules above. Each service has one definition per build branch where the shim and the kernel differ; the typed form is the userspace one and the raw-argument form (`unsigned long a0, ...`) is the kernel one. Names with no definition resolve to NULL and return `STATUS_NOT_IMPLEMENTED`.
- **Locking.** The modules use two build flavours: a userspace shim (`!__KERNEL__`, pthreads) and the kernel build (`__KERNEL__`). Lock primitives differ between them, and some functions have separate bodies per branch.
- **Security.** The token and security-descriptor services in `security` (`NtQuerySecurityObject`, `NtSetSecurityObject`, `NtAccessCheck`, the token services) call `se_access_check`. The object-creation and open paths in `object`, `handle`, `registry`, `io` and `mm` do not. The access checks that exist in those modules are local rules (for example the Machine-hive write rule in `registry`).
- **Image sections.** `mm` plans a `SEC_IMAGE` file with `image_plan` and applies relocations with `image_reloc`. Both are header-only and used only by the userspace build.

## Files not covered here

These files are in `src/kernel/nt/` but are not part of the modules above: `nt_obj.c` (service wrappers for object-directory and symbolic-link objects, events, mutants and semaphores, `NtDuplicateObject`, `NtClose` and the object-information services; its own dispatch entries are summarised in the module pages that use them), `nt_services.c` (event, mutant and semaphore query and set wrappers, timer resolution, `NtRaiseHardError`), `kshim.c` and `kshim.h` (the kernel shim layer), `weak.c` (weak thread-teardown hooks), `repro_mem_vad.c`, and the `*_test.c` and `debugfs_tests.c` test drivers.
